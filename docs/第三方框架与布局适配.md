## 请求与会话规则

- 所有业务请求走同一个 Alamofire Session，不保留另一条仅给测试使用的 URLSession 执行分支。
- 请求头、请求体及返回 DTO 保持现有接口契约；未登录 Authorization 为空，设备号和秘密凭证仍分开使用。
- 不自动重试写请求，不自动跟随重定向，不共享 HTTP Cookie/认证存储，不缓存登录响应；已接入的内容读取由账号与环境隔离的业务缓存按 TTL 和写入失效规则管理。
- 自动刷新仍由 QFAppSession 统一负责；保留刷新并发合并、幂等键及旧响应竞态规则，不重复引入第二套刷新拦截器。
- Debug 日志保留原始字段；非 2xx 仍解析服务端 code/message/requestId；底层 URLError 和取消向业务层传递，响应大小上限保持 2 MiB。

## 图片规则

- 图片使用独立 HTTPS 下载器，不携带业务 API 的 Token、Device-Id 或 Cookie；重定向目标同样校验 HTTPS。
- 缓存 key 包含环境名、API地址、用户ID和图片URL的哈希；不同用户或环境的同 URL 不共用缓存项。
- 全局头像缓存的内存淘汰预算为 8 MiB / 100项，磁盘淘汰预算为32 MiB，过期7天；SDK定期及写后清理。预算是淘汰规则，不是进程RSS或瞬时磁盘的硬上限。
- 缓存使用系统 Caches 目录；图片失败继续显示既有头像占位，菜品默认图和食材 Emoji 规则不变。

## 布局使用方式

按用户最新决定，所有现有页面统一改成 Swift + UIKit + SnapKit。生命周期使用 AppDelegate/SceneDelegate，原生滚动、分页和列表控件通过 SnapKit 约束；不再使用 SwiftUI 页面，也不使用 UIHostingController 包装旧界面。网络和会话仍以 async/await、Combine 驱动。

布局按当前窗口的可用点数判断，不按设备型号判断。主页面容器最大宽760pt（两侧各20pt，内容最大720pt）、Tab最大宽760pt、认证表单最大宽520pt；背景铺满。宽度低于360pt时，筛选和功能卡允许换行或单列；高度低于500pt时，欢迎/登录压缩插画和留白，安全须知允许滚动。底部 Tab 跟随系统 keyboardLayoutGuide，在键盘弹出时上移；切换 Tab 收起键盘且保留页面状态。iPad 开启四个方向；iPhone 保留现有竖屏产品设置。未来新设备需按实际系统与硬件验收，本轮不声称已验证未发布机型。

## 保留的官方能力

- UIKit：横向分类 UIScrollView、欢迎 paging、日志 UITableView、系统弹窗与输入；业务列表接口接入后再配合 UIRefreshControl 与分页规则，不在本地样例列表上伪造刷新/加载请求。
- Security / AuthenticationServices：Keychain 与 Apple 登录。现有Keychain约50行是官方接口的薄适配，保留原服务名、账户名、OSStatus和ThisDeviceOnly属性，避免无必要凭证迁移。
- Codable / Foundation：JSON与日期；没有引入功能重复的YYModel/SwiftyJSON。
- 后续已规划的扫码、图片选择、OCR、视频分别优先使用 AVFoundation、PhotosUI、Vision、AVKit；页面开发时接权限与业务，不在本轮凭空申请权限或添加入口。

Java 当前 Spring Boot/Security、MyBatis、Flyway、HikariCP、Caffeine、Jackson、Nimbus 已覆盖登录与配置业务。本轮不更换认证/ORM，也不新增管理或健康接口。后端依赖升级按独立变更验证。


## 2026-09-13 原生交互与缓存

新增 [MBProgressHUD](https://github.com/jdg/MBProgressHUD)（MIT），SPM 精确 revision `4a7c5f3e53cdea77c5dcb8578c2ee5acacdf6781`，tools5.9，最低iOS9，当前工程最低iOS15；无外部传递依赖，自带隐私清单。许可证已追加 Resources/ThirdPartyAcknowledgements.txt，Package.resolved 已更新。仓库未归档，最近推送2024-08-14，属于更新较少的稳定小库；本轮实际完成当前工具链编译兼容检查，不把星数当维护保证。

采用 UIView 上的延迟 HUD，350毫秒内完成的操作不显示，最短显示300毫秒。首次未加载内容可显示加载 HUD；已有内容返回和缓存读取静默；主动下拉只用 UIRefreshControl；保存/上传显示具体动作。鉴权错误不进入缓存，写入不自动重试。新的内容响应缓存以 Foundation NSCache 为容器，仅是业务失效适配；网络、认证、图片与布局继续复用既有框架。

- `QFContentCache`：按API环境、地址、账号、路径和排序后的JSON查询隔离；读请求合并，通用内容120秒、目录600秒、偏好字典86400秒；并发写入使相关旧读失效，过期响应不能覆盖新写入。公开资料/兴趣/统计的小型本机快照用于即时展示，保存响应先更新缓存。
- 作品、收藏、贡献、账单、投诉、目录、详情和做菜记录使用按ID/内容版本更新的行，未变条目不重新创建图片或控件。首次读取失败不积累提示行，已有数据失败保留并轻提示。
- 受保护媒体仍经原有鉴权接口读取。上传后的图片字节进入32MiB/40项NSCache，120秒有效，单项缓存不超过8MiB；已解码图片复用Kingfisher独立64MiB/60项内存缓存，120秒、不写磁盘。资料保存仅重绘变更字段，国别选择不读接口。
- 设置值按账号存储；只把实际修改设为待同步，350毫秒防抖。进入设置先读取缓存/接口，只有未同步的修改才PUT，不再每次打开覆盖服务端。
- `UITabBarController` + 各Tab独立`UINavigationController`，业务push，原生边缘返回；表单未保存时按草稿/放弃确认。相册、裁剪、全屏媒体、系统警示保留相应呈现方式。
- 发布图片使用分页UICollectionView和UIPageControl，封面字段独立；数量与当前张数局部更新。分段分类支持左右手势，图片自身的分页和系统返回手势优先。

原有上方“底部Tab跟随键盘上移”的实现已被原生UITabBarController替代，使用系统键盘与Tab行为。以上改动未启动App或模拟器，实际侧滑手感、键盘、布局与性能测量由用户验收，不把编译结果作为视觉验收。

## 2026-09-28 个推客户端 SDK

计划提醒需要 APNs 与个推 CID 的正式链路，因此采用个推官方 SPM 二进制包，不自行实现长连接或 Device Token/CID 绑定。GTSDK 固定 3.1.2.0 revision `464c86e453c9c06e23d71bcad3958d1f1b7a68ab`；GTCommonSDK 使用无 IDFA 的 3.2.6.0-noidfa revision `80d402955ea0980730984c3d2d349dff9c2fe649`。两者为 MIT，许可原文和 revision 已加入 `Resources/ThirdPartyAcknowledgements.txt`；官方二进制自带隐私清单。

工程只保留配置读取、同意门禁、CID 与服务端设备登记、语言同步、通知回调、停用和注销恢复的薄适配。AppID、AppKey、AppSecret 从未提交的本地 xcconfig 或 CI 注入；服务端 MasterSecret 不进入客户端。官方 SDK 自动关联 APNs Device Token 与 CID，不另写一套 token 绑定逻辑。完整配置和合规边界见[个推接入记录](getui-ios-integration-20260928.md)。

`Package.resolved` 已手工加入两个官方精确 revision，但本机在线解析先后遇到 SwiftPM 缓存目录冲突和 GitHub TLS 失败，尚未由 Xcode 在线依赖解析验证，也没有运行 Xcode 构建。网络恢复后需让 Xcode 解析并审核锁文件，不把手工 pin 记作构建通过。

## 2026-10-06 采购花销图表

### 2026-10-06 小票二维码（计划19）

检查现有SPM依赖，没有扫码专用包。本页采用Apple官方AVFoundation/PhotosUI/Vision，复用UIKit/SnapKit导航和权限机制。实查[AVCaptureMetadataOutput](https://developer.apple.com/documentation/avfoundation/avcapturemetadataoutput)与[QR对象类型](https://developer.apple.com/documentation/avfoundation/avmetadataobject/objecttype/qr)，同时查看[Mercari QRScanner实现](https://github.com/mercari/QRScanner/blob/master/QRScanner/QRScannerView.swift)。后者也是AVFoundation薄封装，本页只需QR，官方SDK已满足相机、相册识别和后台停止，不再增加重复相机状态/视觉覆盖层依赖。

相册使用PhotosUI单图选择，不请求整个相册授权；仅对用户选择的图片本地解码二维码，不上传照片、不自动访问二维码URL。模拟器Vision使用CPU路径，真机使用系统默认路径；两者检查证据分别记录。商家二维码可能只包含查询标识，没有商家查询数据合同不能构造菜名/配料/金额，当前提示可手工录入采购明细，扫码成功不等于自动入库。
