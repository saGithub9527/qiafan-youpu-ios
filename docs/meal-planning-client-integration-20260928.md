## 已接页面链路

| 范围 | 客户端调用 | 页面行为 |
|---|---|---|
| 家庭范围 | `GET/PUT/DELETE /me/households*`、成员、邀请、权限与所有权接口 | 个人／家庭范围选择、家庭及成员管理、邀请创建/撤销/接受 |
| 计划 | 日历、当天、分页列表、单条详情、单条保存/删除、餐次替换/清空、备菜汇总 | 主计划页、菜谱加入/取消计划、提醒点击定位；餐次移除直接合并服务端返回值，不额外整页刷新 |
| 采购单 | 列表、生成、重生成、明细修改、确认、删除 | 食材页待采购列表、历史采购单选择/分页、备菜页生成入口 |
| 库存 | 分页库存、入库、调整、流水、按计划扣减、任务查询/重试/取消 | 食材库存、做菜打卡和扣减状态页 |
| 提醒 | 提醒配置读写、个推设备登记/停用 | 隐私同意与提醒开关门禁、CID 登记、语言更新、退出停用 |
| AI 周计划 | 提案创建、分页、详情、接受、取消 | 计划页的 AI 周计划列表、生成表单和提案详情 |

采购单列表响应包含完整 `items`，从选择页返回直接使用该响应，不立即请求详情。后续返回或下拉时通过 `GET /me/shopping-lists/{id}` 刷新当前选择；普通返回允许缓存，下拉强制读取。已删除单会回退其他采购单。选择页复用已有 MJRefresh 上拉机制。

本次修改与剩余事项见 [三端续接交付清单](../../../后端/qiafan-youpu-server/docs/meal-planning-cross-stack-20260929.md)。本地源码尚未构建或部署，不等同于测试服已更新。

## 一致性规则

- 界面语言仍是本地设置；每个请求通过 `Accept-Language` 发送语言码，目录正文只返回该语言中可用的数据。采购单目前保留生成时的语言快照，历史选择页显示该单 `language`，切换界面语言不会翻译旧单正文；这项限制尚未解决。
- 个人／家庭范围按环境与用户持久化。备菜、AI 周计划、库存编辑/流水和提醒编辑固定使用进入页面时的范围，导航标题显示该范围，避免编辑中途静默改到另一家庭。
- 列表读取可以刷新；保存和删除优先把服务端返回对象合并进页面缓存。计划餐次整体替换/清空使用 `expectedSlotRevision`，冲突时让用户刷新，不覆盖他人修改。
- 做菜记录先独立保存，再以记录 UUID 作为幂等键创建库存扣减任务。第二步失败时明确显示“记录已保存”，并保留重试入口。
- `PLAN_REMINDER` 通知只在用户点击后读取 `plannedMealId` 并定位计划；前台展示和静默回调不会改变导航。
