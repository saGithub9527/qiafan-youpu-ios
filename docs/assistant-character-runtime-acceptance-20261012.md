# Hunyuan3D 角色修复与验收（2026-10-14）

> **2026-10-14 补充：角色动作尚未通过验收。** 用户继续报告变形，进一步边拉伸检查证实问题仍存在；下文 13 项通过是此前历史检查，不能等同于动作正常。本轮刚体分片、骨骼热权重与包络权重试验均未采纳，APP 已恢复原运行资产以避免混入试验文件。动作/表情选择与顶层窗口代码已写入，最后修正后未重新构建和验收。后续路线与重构门槛见 `docs/assistant-embedding-decision-20261014.md`。

这份记录替代此前仅按骨骼名、表情名和加载成功给出的通过结论。原 Hunyuan3D PBR 角色继续使用；本轮重做源坐标、骨骼分区、服装/手部权重、表情区域与胸牌挂点，APP 浮层几何仍为 92×112 pt。

## 已核实的问题与修复

旧脚本用世界包围盒判断局部 vertex.co，导致头、胸、手臂实际受腿部骨骼控制；原 6 个表情 target 有名称但位移全为零，默认权重又全部为 1。旧运行文件已退出 APP，保留为反例，新的二进制门禁能拒绝它。

新脚本先烘焙节点变换、统一 Z-up 坐标再绑定。骨骼关节按这个角色的大头短身比例校准；躯干使用连续权重，围裙/后蝴蝶结排除臂部影响，手掌与指尖使用独立包络，裙摆跟随骨盆而非腿。每个顶点最多四个影响，归一化后导出。共有 18 根骨骼，其中 root 是控制骨，17 根形变骨均有真实权重。

实际 SCNRenderer 对照确认旧导入 PBR 材质会把脸和头发洗白。浮层现在建立独立 constant 材质、加载原模型的 2K 基础色，保留其绘制的阴影与色彩；原始 PBR 三张贴图保存在 GLB 主文件。USDZ 只运输 rest 蒙皮、表情与 UV，不内嵌贴图，避免导入器将 ZIP 当作图片探测。这里没有更换角色、改成静态人物图片或加入新渲染 SDK。

眼斑的实际 Z 区间约 .696～.736，嘴线中心约 .667。表情区域已校准，默认 10 个通道均为零，除 neutral 外均有真实位移。直接强压眼斑仍会使绘制纹理折成黑块，因此 APP 增加随头骨运动的独立眼睑及闭眼线，眨眼只保留 .08 的轻微 morph 贡献。情绪、眨眼和预留 talk 通道互不清零；本轮尚未接通语音口型同步。

徽章成为 chest 骨骼子节点，源坐标 (-0.060,-0.145,0.490)，平面大小 .065；位置和朝向从该模型的坐标转换，位于胸前并跟随躯干。旧的外层骨盆坐标不再用于 Hunyuan 角色。

## 动作接入

GLB 与 USDZ 均为静态 rest 资产，导入节点动画会被移除；APP 的一个控制器负责所有骨骼写入。骨骼旋转在 bind transform 上叠加，把源弯曲轴转换到每根骨骼的 rest 坐标，避免把局部长度轴的扭转误当抬手。

idle/greeting/thinking/positive/sad/awkward/angry 动作族从兼容片段中随机选择，并变化幅度、停顿、手腕方向或抬脚侧。挥手保持手臂抬起，再交替摆动前臂/手腕；捂面把双手转到脸前；抬脚由一条腿弯曲完成，另一只脚保持着地。动作结束恢复待机。整个人物的上下浮动已移除。

当前意图仍由界面事件与本地文本规则提供，不把它称作完整场景语义理解。英文匹配已使用整词，thinking/this/chicken 不再被其中的 hi 误识别为招呼。取消的旧请求和关闭后的响应不能重写当前动作；停止/后台后的迟到动作不能重新开启场景。待机与眨眼任务使用弱引用，停止时都取消。开启减弱动态效果时不运行循环动作/眨眼。
