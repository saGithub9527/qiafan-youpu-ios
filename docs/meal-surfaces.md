# 下一餐在哪里看

用餐计划使用同一份数据展示在三个位置：App 首页的固定卡片、用户添加到手机桌面的“下一餐”小组件，以及用餐前的锁屏实时活动。支持灵动岛的手机还会显示简洁计时，长按可以展开菜谱和食材。

首页和桌面会显示日期、餐次、菜谱，以及已有和待采购的食材摘要。点击后进入当前账号有权查看的计划。没有计划时显示空状态；读取失败或库存未核对时，不会写成“食材已备齐”。已完成或跳过的计划不作为下一餐。

桌面小组件需要用户在 iPhone 桌面长按，选择添加小组件，再搜索“恰饭有谱”。App 无法自行把它放到桌面。当前提供小号和中号。App 同步最多未来八天的只读快照；超过一天未成功刷新时，小组件提示打开 App 更新，避免把旧库存当作当前库存。

实时活动在餐前四小时内开始，餐次完成、取消、超时或关闭提醒后结束。iOS 16.1 起支持本机创建；服务器自动创建需要 iOS 17.2 及以上。iPhone XR 可以显示锁屏实时活动，但没有灵动岛。iOS 第一次远程创建可能要求用户在系统界面允许；供应商受理和苹果 HTTP200 都不代表已经在手机显示。

苹果限制单次实时活动最多运行八小时。这里按每一餐创建，首页卡片与桌面组件承担长期查看的用途。实时活动被用户移除后，不会在每次刷新时重新拉起同一餐。

## 数据与权限

UIKit 首页与 WidgetKit/ActivityKit 扩展共用 Shared/QFMealSurfaceModel.swift。App 将当前账号、家庭和语言绑定到不含原始身份的范围哈希，只向 App Group 保存显示数据。桌面与锁屏不会读取聊天、模型文件或登录令牌。

切换账号、家庭和语言会重新同步；退出或关闭提醒会清除展示。点击计划仍由现有计划接口重新校验权限，不凭页面链接直接写业务数据。

服务端仅增加设备和实时活动投递元数据。原有计划、库存、采购不因显示提醒而修改。APNs 凭据只保留在服务端，设备与活动令牌加密存储；开始、更新、结束有持久投递状态，不能在不确定失败后重复创建。

测试环境的自动活动发送限定当前验收账号与 XR；普通计划通知发送器保持关闭。Release 配置和其他账号的正式发送尚未开放。

## 开发检查入口

DEBUG 的 `-QFReadMealSurfaces -QFCheckRun <UUID>` 只导出注册和系统状态，不导出令牌或业务正文。

DEBUG 的显示检查要求已登录测试环境、明确的单次 UUID、一次性 RSA 公钥以及最长三分钟的内存租约。检查内容明确标记“未保存饮食计划”，不写计划、库存、共享组件缓存或产品投递表。能力令牌只导出密文，结束后删除；没有业务跳转。该检查不会在正常启动或 Release 中执行。
