# 计划08：做菜记录

2026-10-03。依据已确认设计档案 `04-计划与备菜/08-做菜记录.png`、同版功能及交付说明；合同 `plan-history-r1`。本页用于计划 Tab 的做菜记录入口，“我的”月历/列表页继续使用其原有交互。

## 页面与数据

固定顶部返回、标题与补记入口。滚动区依次为本月完成/下厨天数双卡、月份与七日日期条、所选日汇总、做菜记录、月成本和菜品使用统计入口。延续奶油白背景、橙绿主色、24pt 页边距、18pt 卡片圆角、90pt 汇总卡及至少86pt记录卡；采用原生 push 返回。

入页请求 `GET me/cooking-records?month=YYYY-MM&date=YYYY-MM-DD&page=0`。每页20条，MJRefresh 上拉加载；下拉从第0页重新读取。导航不属于下拉区域。日总数、完整日成本、整月完成数、下厨天数、记录日期、分币种金额及缺失成本数直接使用服务器聚合结果，不对已经加载的一页求和冒充全部数据。缺失成本显示待补全，各币种分别展示，没有自动换汇或用0替代未知金额。

七日条左右按钮按周切换；可选择范围中的具体日期。最近10个日期的页面快照保存在当前控制器内，120秒内切回直接复用；过期才重新读取。不同日期和语言的迟到响应不能覆盖当前页。下拉刷新强制绕过请求缓存。列表使用稳定记录ID去重和 diffable 更新，空页/重复页会停止自动上拉，避免循环请求。

初次读取在内容区显示加载占位，汇总未知值为“—”；首次失败在列表内显示重试卡，不显示虚假的零记录。已有数据刷新失败保留内容。上拉失败交给列表底部重试状态，不用全屏加载提示。

主计划历史日期的“已做”入口携带所选日期，避免误开今天。补记沿用同日多菜/多餐本地草稿；未来日期不允许提交。实际扣库存记录进入09页，其余记录进入现有编辑页。子页成功写入才清除本页日期快照，返回时强制刷新已展示页；未修改直接返回不发额外请求。菜品统计入口按所选月份读取现有月列表，不改变“我的”原有按日统计口径；10号统计页面的完整设计验收仍单独待办。

## 复用与边界

已检查现有 SPM 依赖，复用 UIKit、SnapKit、MJRefresh 和现有请求缓存。本轮核查 [MJRefresh 官方仓库](https://github.com/CoderMJLee/MJRefresh) 和 [Apple diffable snapshot 文档](https://developer.apple.com/documentation/uikit/uitableviewdiffabledatasource)。不新增刷新、网络或持久化框架。共享列表仅增加默认仍为20pt的可选页边距，08使用24pt；共享读取执行器仅增加默认开启的初次读进度开关，08使用局部加载态。

增加10条可见文案，八份翻译资源加源码中英共同覆盖10语言。接口正文仍按请求语言处理；用户自己的历史菜名是用户输入快照，不擅自机翻。

后端接口契约及参数校验见 `后端/qiafan-youpu-server/docs/cooking-record-day-pagination-20261003.md`。这是当前登录用户的只读页，无新管理后台编辑流程、无H5页面或数据库迁移。复用现有索引和 Spring/MyBatis 聚合查询。需要先部署支持新响应的后端，再交付客户端；本轮不声称已部署。
