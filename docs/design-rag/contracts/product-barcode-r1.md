# 商品包装条码扫描 r1 · 2026-10-17 用户明确变更

用户要求用商品包装上的条形码替代小票识别，并明确“不是扫描小票的二维码或条形码”，随后要求去掉小票扫描功能。牙线仅为扫码举例，本次仅处理食材。此要求覆盖 receipt-scanner-r2 的小票QR/OCR交互。

沿用深绿色扫描页、固定顶部返回/居中标题、居中方框/扫描线、相册和手电筒的位置。原拍小票入口替换为手动填写。标题、入口、权限与无障碍文案均为扫描商品条码。去除小票QR/Taiwan发票/文字识别运行代码与入口，不提供自动OCR回退。

使用原生 AVFoundation EAN13/EAN8/UPCE，不启用小票交易或物流常见的Code128、QR，照片由Vision在设备识别；只处理明确选中的一个商品，不依据小票列或包装净含量推断购买数量、成交金额。GTIN校验、前导0、UPC-E展开；受限流通码仅留本机，不盲目联网。拍到多个商品码时供选择；小票二维码无匹配。

可向固定Open Food Facts食品API发送单个合格商品编码与界面语言，匿名读取品名建议，照片和App认证不发送；保留公开数据来源署名，查无/失败/超时直接手工编辑。用户可立即跳过查询手动填写。

商品名称为独立可编辑文本框，食材关联为独立选择控件，改名不改变食材ID。数量1是需核对的可编辑初始值，价格未知留空，不作0元。条码与资料来源只作为客户端草稿提示，不改变现有采购API。

新扫商品可明确加入既有草稿；同码不重复累计，使用原条目手工改数量。未决保存冻结草稿不能追加，最多40项。多商品可在编辑页继续扫码。商品信息、数量、单位与价格需用户确认，最终保存才走既有幂等采购/库存写入。旧账单与旧草稿可继续读取，不删除旧数据。

相机离页/后台停止，异步查询与相册结果绑定账号、家庭、语言和本次操作，不将迟到结果推入其他范围。保留边缘返回和原有采购页固定底部保存。
