# 制定计划与为计划选菜（2026-09-30）

本阶段仅完成设计 03/04 及直接依赖：单日／日期范围、指定星期、三餐多选、本地草稿、一次批量保存。后续「调整当餐计划、完成确认、撤销与成本」独立推进，不以网络层已有函数代替页面完成。

## 页面与状态

- 依据 `全球菜谱APP-设计档案/01-当前设计/04-计划与备菜/03-制定计划.png`、`04-为计划选菜.png` 与功能覆盖说明。已登记 `plan-create-r1` RAG 合同；保留奶油白、橙绿、三餐卡片、固定导航和底部保存区。
- 手动制定入口进入新表单。日期范围首尾包含、最多 42 天；每周重复只在选定范围内按 ISO 星期展开，不是无限期后台任务。单日模式忽略此前范围／星期，不暗中提交隐藏值。
- 每餐最多 30 道，支持单菜 1–100 份与移除；保存计划不扣库存。三餐可留空，但至少选一道。日期或重复规则无有效日期时，显示错误并禁用保存。
- 选菜固定搜索及来源，列表复用 UITableView、MJRefresh；全部／收藏／经常做可点选与横滑，按语言、来源、搜索词独立保留分页及滚动位置。多选跨页保留，加入当前草稿时才回传选择，不调用写接口。
- 单日选菜读取当前餐次，标记已有项；范围模式由最终事务按各日去重，不把首日已有误判为整个范围不可选。并发增加或目录下架由最终事务校验。
- 本地草稿沿用现有用户＋环境隔离存储，再按个人／家庭区分。页面返回可保留或丢弃；未登录不会创建服务器草稿。不新建服务器草稿表。
- 固定 requestId、body、语言在首次请求前本地落盘。网络不确定时保留回执、禁用编辑、允许同一请求重试；认证/权限/一般限流错误不证明之前未提交，也不丢弃回执。只有批量专用的目录不可用 42201／容量 42204 才恢复编辑。未确认回执不能被「放弃草稿」删掉。
- 成功清除本地草稿并使相关缓存失效。服务器重放的 days 是历史快照，主计划按需要读取当前 day，不覆盖为旧响应。语言属于本地设置；所有业务请求携带语言码，未知结果重试使用首次保存的语言。
- 新增文案同步覆盖全部十语；不同语言的旧草稿不会把旧语言菜名当成当前正文显示。

## 接口、数据库与管理后台

接口详情见后端 `docs/meal-plan-batch-20260930.md` 及 OpenAPI：

1. `POST /api/v1/me/planned-meals/batch`：日期范围、weekdays、三餐多菜、家庭范围、requestId，一次事务追加与持久幂等回放。
2. `GET /api/v1/catalog?type=RECIPE&source=ALL|FAVORITE|FREQUENT&q=...&page=...`：复用现有目录接口，新增来源及当前语言材料名搜索。
3. `GET /api/v1/me/planned-meals/day`：读取当餐已有菜品；不在选菜时调用保存接口。

数据库新增 V36 幂等回执表；不修改菜谱数据、不清空任何既有表。真实迁移、并发锁行为和搜索执行计划仍需要独立 MySQL 验证与部署；Mock 单元测试不能代替。

管理后台代码已核对 `ReferenceDataView.vue`、`CatalogImportPanel.vue`、路由及公开字段：已有十语名称／材料编辑、发布状态与 Excel 导入，可继续供应本页数据。收藏和经常做为用户关系派生，不需让管理员人工维护；本轮不额外开放用户私人计划查询或编辑。H5 目前无已确认计划编辑页面，这次不添加页面或协议条款。

“经常做”当前只能统计仍能通过计划关联识别菜谱的真实做菜记录；计划外补记、删除计划后失去关联的记录不计，后来换菜也可能影响历史归属。后续做菜记录页应持久保存 recipeId 快照，不能将现在的结果当成完整终身统计。
