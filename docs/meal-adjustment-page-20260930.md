# 调整当餐计划（设计 05）

2026-09-30。依据已确认的 `04-计划与备菜/05-调整当餐计划.png`、功能覆盖和设计交付说明；RAG 基线 `plan-adjust-r1`。

## 客户端行为

- 点击餐次更多菜单，单菜直接展示操作，多菜先选择目标；点菜名也可直接调整该菜。使用原生底部菜单，保留奶油背景和橙绿主题。移动与换菜编辑继续 push 导航。
- 操作顺序：换菜、移动日期／餐次、跳过本次（已跳过时显示恢复）、移出计划。已完成菜品不能换菜或跳过，可以移动安排或移出；真实做菜记录的日期不因此更改。
- 换菜复用已有搜索／收藏／常做列表、下拉刷新与 MJRefresh 分页；仅选一道，确认后提交。已有当餐菜品禁选。
- 日期／餐次草稿使用账户及环境隔离的本地缓存。调整控件不调用写接口，保存才 PUT；失败保留草稿。并发冲突不会自动用新版本覆盖，可明确确认丢弃当前草稿并重新载入。
- 跳过保留安排，恢复可再次参与待做计划；已跳过不进入当日待完成进度。移出前确认，服务端保留已发生的做菜历史。
- 所有编辑保留 recipeId、servings、householdId，携带 expectedRevision。返回失败后重试遇到 409 时，仅当重新读取的完整目标状态一致才作为已成功处理；不盲目覆盖其他家庭成员的修改。
- 成功后失效相关缓存，重新获取当前日／月；打开菜单、修改草稿、选择日期不触发计划刷新。

## API

复用 `PUT /api/v1/me/planned-meals/{id}` 与 `DELETE /api/v1/me/planned-meals/{id}?expectedRevision=...`。

PUT 保留现有字段，并新增可选 `skipped: boolean`；省略时保留原状态，新建默认 false。所有 PlanItem 返回 skipped。客户端读取旧响应时默认 false，写操作依赖新后端上线。409 表示版本或状态冲突，换菜缺少请求语言已发布内容返回 42201。

服务器新增 V37 跳过状态、历史 recipeId 快照。完整服务端变更以该阶段后端说明和 OpenAPI 为准。界面语言仍由客户端本地保存，通过 Accept-Language 传递。

## 组件调研

已检查现有 UIKit、SnapKit、MJRefresh、JXSegmentedView 依赖；实际检索 [Apple UISheetPresentationController](https://developer.apple.com/documentation/uikit/uisheetpresentationcontroller) 和 [FloatingPanel 官方仓库](https://github.com/scenee/FloatingPanel)。本页不需要地图式持续浮层，系统 sheet 已提供拖拽、关闭和大字扩展，故采用系统组件，不新增第三方依赖。iOS 16+ 自定义初始高度并允许拉大，iOS 15 用 large detent 保证操作可见。
